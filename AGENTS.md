# «Пора» — правила для работы с кодом

- Начинайте с [`docs/PROJECT-MAP.md`](docs/PROJECT-MAP.md): там модули, точки входа и какие тесты запускать для каждой области. Карту, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md` и `docs/CHANGELOG.md` обновляйте в том же PR, что и код.

- Язык интерфейса, документации и коммитов — русский, простыми словами. Комментарии в коде — по-английски или по-русски, коротко.
- Никаких секретов в коде, образе и документации: пароли и ключи живут только в `.env` на NAS.
- Никаких личных имён в коде и документах.
- Не упоминать названия других приложений-планировщиков (CI: `node scripts/brand-check.mjs`).
- Интерфейс плотный и компактный, пояснения — за значком «?».
- Перед изменениями интерфейса — скриншот настоящего приложения.
- Синхронизация: модель документа и слияния — `src/lib/sync/merge.ts`, один прогон — `src/lib/sync/engine.ts`, браузер — `src/lib/server-sync.ts`, сервер — `server/routes/api/sync.*.ts`.
- Перед пулл-реквестом: `npm run typecheck && npm test && npm run lint && node scripts/brand-check.mjs`.
- Сборка образа — GitHub Actions → GHCR; обновление на NAS вручную (см. `docs/SYNOLOGY.md`).
