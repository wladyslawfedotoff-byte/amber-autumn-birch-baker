# Пора — время делать

**«Пора»** — личный планировщик: задачи, календарь, привычки и фокус-таймер в одном приложении. Работает в браузере и как PWA на телефоне, хранит данные локально (офлайн) и синхронизирует их через собственный сервер — например, Docker-контейнер на Synology NAS. Профили (например, для двоих в семье) задаются в `.env` на сервере, сторонних аккаунтов нет.

Название и слоган заданы в одном месте — [`src/lib/og/site.json`](src/lib/og/site.json) (`title`, `tagline`, `description`); оттуда их берут страница входа, боковая панель, `<title>`, мета-теги и PWA-манифест (через [`src/lib/site.ts`](src/lib/site.ts) и `scripts/grok-pwa-*.mjs`).

## Возможности

- **Задачи:** «Входящие», «Сегодня», «Завтра», «7 дней», «Все»; списки, подзадачи, приоритеты, повторы (в том числе **«Выбранные даты»** — задача появляется ровно в отмеченные в календаре дни), напоминания.
- **Профили и общие задачи:** у каждого свой логин, пароль и свои данные. Задачу или список можно сделать **«Совместной»** или **«Назначить»** другому профилю — она появится у него во «Входящих», в «Сегодня» и в календаре, а у вас будет видно «выполнил(а) Пользователь 2». Все общие дела — в разделе **«Общие»**. Пароль меняется прямо в «Настройках».
- **Быстрый ввод по-русски:** «завтра в 9 позвонить врачу» — дата и время распознаются из текста.
- **Календарь и расписание:** раскладка задач по дням и часам, перетаскивание, рабочие часы.
- **Проекты** (канбан), **матрица Эйзенхауэра**, **даты** (вехи и обратный отсчёт).
- **Готово и архив:** выполненная задача зачёркивается и уходит в сворачиваемую группу «Готово» внизу списка (с кнопкой «Отменить»); через N дней (1/2/3/5/7/30 или никогда — в «Настройках») — в «Архив», откуда её можно вернуть или удалить.
- **Цвета задач** — своя палитра из 10 цветов: полоса в списках, точки в календаре, цветные блоки в расписании.
- **Расписание на 1, 2, 3, 5 или 7 дней:** день по часам или несколько дней рядом — задачи, памятные даты и привычки.
- **Памятные даты:** вводится исходная дата (рождения, свадьбы) — «исполнится 35», «10 лет свадьбе», «через 12 дней»; год можно не указывать, 29 февраля учтено. У даты есть списки: идеи подарков (со ссылкой и ценой), идеи, дела, покупки; напоминание за N дней; можно сделать совместной.
- **Привычки** (серия, лучшая серия, % за 30 дней, карта месяца) и **фокус-таймер** (помодоро).
- **Помощник** (необязательно): чат по вашим задачам — план дня по свободным окнам, шаги для задачи, задачи и привычки из текста. Изменения приходят карточками и применяются только после «Применить». Модели: свой ПК в домашней сети и/или облачные сервисы по очереди (бесплатные первыми); «Отложить», если никто не ответил.
- **Синхронизация** между устройствами через свой сервер: ревизии, слияние по записям, офлайн-очередь; резервные копии на сервере и ручной экспорт/импорт в настройках.

- **1.6.1** — «Помощник» надёжнее с облачными моделями: если сервис не выполняет функции (модель отвечала «нет доступа к инструментам»), вопрос сам переспрашивается в режиме JSON, и предложения по-прежнему приходят карточками с «Применить»; режим можно задать для каждого сервиса (`AI_<ИМЯ>_TOOLS=auto|json|native`). Модель всегда видит краткую сводку: просроченное, сегодня, ближайшие 7 дней и свободное время по дням. Ответы с оформлением: жирный, курсив, списки, ссылки (без HTML). Исправлено: начало ответа иногда пропадало при нестандартной разбивке потока.
- **1.6.0** — новый «Помощник»: чат по вашим задачам. Подсказки на пустом экране («Спланируй мой день», «Разбей задачу на шаги», «Добавь дела из текста», «Что у меня просрочено?»), ответ появляется по мере набора, ввод голосом, история бесед (☰, удаление) и «Новая беседа». Всё, что помощник предлагает создать или изменить (задачи с датой, временем, списком, приоритетом и шагами, перенос и выполнение, шаги для задачи, план дня по свободным окнам, привычки), приходит карточкой: пункты можно поправить или убрать, изменения — только после «Применить» и синхронизируются как обычно. Помощник видит только данные вошедшего профиля. Модели задаются на сервере: ПК в домашней сети (Ollama или LM Studio, тип определяется сам) и/или облачные сервисы по очереди (бесплатные первыми, платная последней; ошибка или лимит — следующая модель, пауза 5 минут, потолок токенов в месяц); значок в чате показывает, кто ответил. Экран согласия перед первым ответом (и при первом переходе в облако). «Настройки → Помощник»: состояние каждой модели, «Проверить связь», «Разрешить облако, когда ПК выключен», «Разрешить платные». Если не ответил никто — «Повторить» или «Отложить»: сервер сам переспросит (до суток), ответ придёт в беседу и в колокольчик. Новый значок приложения (восходящее солнце над горизонтом с галочкой): на экране «Домой», в установленном приложении (обычный и «маскируемый» варианты), во вкладке браузера, на странице входа и в меню; ссылки на значки с версией, чтобы устройства подхватили новый.

## Технологии

React 19, TanStack Start / Router, Vite 8, Nitro 3 (preset `node-server` для Docker), Tailwind CSS 4, Zustand. Данные синхронизации — JSON-файл на сервере (`DATA_DIR/pora.json`), база данных не нужна.

## Локальная разработка

Нужен **Node.js 22** (см. `engines` в `package.json`).

```bash
npm ci
# сервер разработки на http://localhost:8080
APP_PASSWORD='локальный-пароль-123' DATA_DIR=./data npm run dev
# два профиля (логины user1 и user2):
APP_USERS=user1,user2 USER_USER1_PASSWORD='пароль-пользователя-1-123' USER_USER2_PASSWORD='пароль-пользователя-2-123' DATA_DIR=./data npm run dev
# или без входа (только локально, в production игнорируется):
AUTH_DISABLED=true DATA_DIR=./data npm run dev
```

Проверки и сборка:

```bash
npm run typecheck   # TypeScript
npm run lint        # ESLint
npm test            # модульные тесты (node --test)

# production-сборка для своего сервера / Docker
NITRO_PRESET=node-server VITE_GROK_EXTENSIONS=0 npm run build
APP_PASSWORD='<своя фраза, 16+ символов>' DATA_DIR=./data PORT=8080 node .output/server/index.mjs
```

Папка `./data` (данные, ключ сессий, резервные копии) и любые `.env` в git не попадают.

## Развёртывание (Docker / Synology)

Образ собирается GitHub Actions и публикуется в GHCR: `ghcr.io/wladyslawfedotoff-byte/amber-autumn-birch-baker:latest` (образ публичный, секретов в нём нет).

- [`docker-compose.ghcr.yml`](docker-compose.ghcr.yml) — готовый образ (рекомендуется для NAS);
- [`docker-compose.yml`](docker-compose.yml) — сборка образа из исходников;
- пошаговая инструкция для Synology Container Manager, Reverse Proxy DSM и HTTPS — [`docs/SYNOLOGY.md`](docs/SYNOLOGY.md).

Структура на сервере:

```
pora/
├── compose.yaml   # без секретов
├── .env           # секреты (см. .env.example), права только для администратора
└── data/          # pora.json, users.json (пароли, сменённые в приложении), backups/, .session-secret, .session-epoch
```

Проверка: `curl http://127.0.0.1:8080/api/health` → `{"ok":true,…}`.

## Переменные окружения

Все секреты задаются в файле `.env` рядом с compose-файлом (`env_file`); подробный шаблон с пояснениями и правилами записи `$` — [`.env.example`](.env.example).

| Переменная | Где | Назначение |
| --- | --- | --- |
| `APP_USERS` | `.env` | Список профилей через запятую, например `user1,user2` (логины: `a–z 0–9 _ -`, до 32 символов). Без него — один профиль по `APP_PASSWORD`. |
| `USER_<ЛОГИН>_PASSWORD_HASH` / `USER_<ЛОГИН>_PASSWORD` | `.env` | Пароль профиля (хэш рекомендуется: `node scripts/hash-password.mjs <логин>`). `<ЛОГИН>` — логин заглавными, `-` → `_`: `USER_USER1_PASSWORD_HASH`. |
| `USER_<ЛОГИН>_NAME` | `.env`, необяз. | Имя в интерфейсе («Пользователь 2»). По умолчанию — логин. |
| `APP_OWNER` | `.env`, необяз. | Чьими становятся данные, созданные до включения профилей (по умолчанию — первый в `APP_USERS`). Его пароль можно не дублировать: подойдёт старый `APP_PASSWORD(_HASH)`. |
| `APP_DEFAULT_USER` | `.env`, необяз. | Логин единственного профиля без `APP_USERS` (по умолчанию `admin`; поле «Логин» тогда не показывается). |
| `APP_PASSWORD` | `.env` | Пароль входа: рекомендуется фраза 16+ символов, минимум 12 (12–15 — предупреждение в журнале). Без него или хэша приложение закрыто (fail closed). |
| `APP_PASSWORD_HASH` | `.env` | scrypt-хэш пароля (`node scripts/hash-password.mjs`), имеет приоритет. Рекомендуется. |
| `SESSION_SECRET` | `.env`, необяз. | Ключ подписи сессий (≥ 32 символов). Иначе создаётся `DATA_DIR/.session-secret`. |
| `AI_PROVIDERS`, `AI_LOCAL_URL` / `AI_LOCAL_TYPE` / `AI_LOCAL_MODEL`, `AI_<ИМЯ>_BASE_URL` / `_API_KEY` / `_MODEL` / `_PAID` / `_MONTHLY_TOKENS` / `_CHECK_URL` / `_TOOLS` | `.env`, необяз. | «Помощник»: очередь моделей (ПК → бесплатные → платная). ПК: `AI_LOCAL_TYPE=ollama`, `lmstudio` или `auto`. `{model}` в `BASE_URL` — свой адрес у каждой модели. Без них пункт скрыт. Подробно — `.env.example`, `docs/SYNOLOGY.md` п. 10. Старые `AI_OLLAMA_URL`/`AI_OLLAMA_MODEL` и `XAI_API_KEY` работают. |
| `PUID` / `PGID` | `.env`, необяз. | Владелец папки данных, если она недоступна для записи. |
| `BACKUP_INTERVAL_MINUTES` | `.env`, необяз. | Не чаще одной резервной копии за N минут (30). |
| `BACKUP_HOURLY` / `BACKUP_DAILY` | `.env`, необяз. | Хранить по одной копии на каждый из последних N часов / M дней (24 / 30). |
| `APP_URL` | compose | Публичный адрес с портом — для проверки Origin (CSRF). |
| `DATA_DIR` | compose | Папка данных в контейнере (`/data`). |
| `VITE_GROK_EXTENSIONS` | compose / сборка | `0` — без стороннего скрипта расширений Grok. |
| `AUTH_DISABLED` | только разработка | `true` отключает вход вне production. |

## Безопасность

- Пароли профилей — в `.env` (scrypt-хэш `USER_<ЛОГИН>_PASSWORD_HASH` / `APP_PASSWORD_HASH` или открытый пароль, сравниваемый по SHA-256 в постоянное время). Пароль, сменённый в приложении, хранится только как scrypt-хэш в `DATA_DIR/users.json` (права 0600, атомарная запись) и перекрывает `.env`; сброс — `docker exec pora-app node scripts/reset-password.mjs <логин>`.
- Права на общие задачи проверяет сервер: каждый профиль получает только свои данные и то, чем с ним поделились; чужие изменения и удаления недоступных записей отбрасываются.
- Без настроенного пароля сервер отдаёт только `/api/health` и страницу «Вход не настроен».
- Сессия — подписанная cookie `__Host-pora_session` (`HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS); 30 дней без использования, не дольше 90 дней после ввода пароля. Сессия привязана к профилю: «Выйти на всех устройствах» и смена пароля в приложении разлогинивают остальные устройства только этого профиля; смена ключа сессий — все.
- Проверка Origin для входа и изменений (точное совпадение с `APP_URL`, включая порт), безопасный редирект после входа, HSTS на HTTPS, ограничение попыток входа (5 за 15 минут с IP и общий порог 50 неудач для новых входов), журнал неудачных входов с IP.
- Контейнер работает от непривилегированного пользователя (`no-new-privileges`, `cap_drop: ALL` + минимальный `cap_add`), драйвер журнала не переопределяется (на Synology журнал хранит Container Manager), порт опубликован только на `127.0.0.1`, наружу — HTTPS через Reverse Proxy.
- Резервные копии: встроенные (по часам и дням) с восстановлением `docker exec pora-app node scripts/restore-backup.mjs`, плюс Hyper Backup — см. [`docs/SYNOLOGY.md`](docs/SYNOLOGY.md#8-резервные-копии-и-восстановление).
- Секреты никогда не попадают в git, Docker-образ или compose-файл: только `.env` на сервере (`.gitignore`, `.dockerignore`).
- Не вставляйте токены GitHub в URL клонирования; используйте SSH-ключ.

## Структура проекта

```
src/
  routes/              страницы TanStack Router (__root.tsx — заголовок, мета, PWA)

  lib/                 состояние (planner-store), синхронизация (sync/, server-sync),
                       быстрый ввод, напоминания, резервные копии
  lib/og/site.json     название «Пора», слоган «время делать» и описание (мета-теги, PWA, вход)
  lib/sync/world.ts    профили и общие задачи: права доступа, представление для пользователя
server/
  routes/              /api/health, /api/login, /api/logout, /api/logout-all, /api/sync,
                       /api/me, /api/password, /api/capabilities, /login
  middleware/          защита процесса, проверка входа, PWA-манифест
  lib/                 хранилище синхронизации, профили и сессии, лимиты, журнал
scripts/               сборочные плагины, hash-password.mjs, reset-password.mjs, restore-backup.mjs,
```
