# Ключи помощника: API для ботов (1.25.0, списки — 1.26.0)

Бот (например, свой ассистент) подключается к «Поре» по **ключу помощника** и создаёт вам задачи. Задачи появляются у вас во «Входящих» с пометкой «от помощника · <имя ключа>»; вы можете править и удалять их как обычные.

## Что может ключ

| Можно | Нельзя |
| --- | --- |
| создать задачу (во «Входящие» или в свой список) | видеть другие задачи, списки, проекты, теги, контакты, настройки |
| создать свой список и переименовать его | класть задачи в чужие списки |
| посмотреть и изменить **свои** задачи: название, заметку, дату, время | удалять что-либо — даже свои задачи |
| отметить свою задачу выполненной / вернуть в работу | входить в приложение, синхронизацию, помощника, вложения и любые другие адреса |
| оставить отчёт «получилось / не получилось» с комментарием | |

«Своя» задача или список — созданные этим ключом (внутри хранится метка автора `helper: { keyId, name }`). Если вы перенесёте задачу в свой проект или список, бот по-прежнему видит только её саму: `listId` в ответе будет `null`, ваш список и проект не раскрываются. Удалили задачу — бот получает 404.

Список бота — обычный список «Поры»: он появляется в боковом меню в «Мои списки» с маленьким значком бота, а в заголовке списка — «от помощника · <имя>». Его можно переименовать, сделать совместным или удалить как любой свой. Если вы удалите список, его задачи ведут себя как обычно (уходят во «Входящие»), бот этот список больше не видит.

## Ключ

- **Настройки → Помощники → Новый ключ**, имя — например «Оркестратор». Ключ вида `porah_…` показывается **один раз**, на сервере хранится только его хэш (sha256).
- Передавайте ключ боту только через защищённое поле, не в переписке и не в репозиторий.
- **Отозвать** — ключ перестаёт работать сразу. Смена пароля и «Выйти на всех устройствах» отзывают все ключи профиля.
- Не больше 5 ключей на профиль. Рядом с ключом видно, когда им пользовались последний раз.
- **Журнал** под ключом: кто, когда и что сделал (создал, изменил, отметил, вернул, оставил отчёт, создал или переименовал список, перенёс задачу; отказы — попытки открыть чужую задачу или список или удалить). Хранится 90 дней.
- Нужна база SQLite (1.12+).

## Адрес

Бот работает не в домашней сети, поэтому ходит на внешний адрес «Поры» по HTTPS — например, через адрес роутера в **KeenDNS**, который ведёт на обратный прокси NAS:

```
https://pora.example.synology.me/api/helper
```

(подставьте свой адрес и порт). Если на NAS включён фильтр по странам или IP, адрес бота должен в него проходить. Ключ — в заголовке:

```
Authorization: Bearer porah_<ключ>
```

Сессии и cookie здесь не принимаются, а сам ключ не работает ни на каких других адресах.

## Запросы

Тело и ответы — JSON. Дата — `ГГГГ-ММ-ДД`, время — `ЧЧ:ММ` (время только вместе с датой); `null` убирает значение.

| Запрос | Что делает | Ответ |
| --- | --- | --- |
| `GET /api/helper/me` | проверить ключ | `{ "name": "Оркестратор" }` |
| `GET /api/helper/tasks` | свои задачи, новые первыми | `{ "items": [задача, …] }` |
| `POST /api/helper/tasks` | новая задача во «Входящие»: `{ "title", "notes"?, "due"?, "startAt"?, "endAt"? }` | `201 { "item": задача }` |
| `GET /api/helper/tasks/<id>` | одна своя задача | `{ "item": задача }` |
| `PATCH /api/helper/tasks/<id>` | изменить: любые из `title`, `notes`, `due`, `startAt`, `endAt` | `{ "item": задача }` |
| `POST /api/helper/tasks/<id>/complete` | отметить выполненной (повторяющаяся переходит на следующую дату, как галочка в приложении) | `{ "item": задача }` |
| `POST /api/helper/tasks/<id>/reopen` | вернуть в работу | `{ "item": задача }` |
| `POST /api/helper/tasks/<id>/comments` | отчёт: `{ "text": "…", "result"?: "ok" \| "fail" }` | `201 { "item": задача }` |
| `GET /api/helper/lists` | свои списки | `{ "items": [{ "id", "name", "updatedAt" }, …] }` |
| `POST /api/helper/lists` | новый список: `{ "name" }`; если у ключа уже есть список с таким названием (без учёта регистра и пробелов по краям) — вернётся он | `201 { "item" }` или `200 { "item", "existed": true }` |
| `PATCH /api/helper/lists/<id>` | переименовать свой список: `{ "name" }` | `{ "item" }` |

В `POST /tasks` и `PATCH /tasks/<id>` можно передать `listId` — id **своего** списка; `null` возвращает задачу во «Входящие». Чужой, удалённый или несуществующий список — `404`, как неизвестная задача.

Задача в ответе:

```json
{
  "id": "…", "title": "Записать машину на ТО", "notes": "…",
  "due": "2026-11-20", "startAt": "10:00", "endAt": "10:30", "listId": null,
  "done": false, "completedAt": null, "createdAt": 1763600000000, "updatedAt": 1763600000000,
  "comments": [{ "id": "…", "at": 1763600000000, "text": "Записали на пятницу", "result": "ok" }]
}
```

Пример:

```bash
curl -s https://pora.example.synology.me/api/helper/tasks \
  -H "Authorization: Bearer $PORA_HELPER_KEY" -H "content-type: application/json" \
  -d '{"title":"Позвонить в сервис","due":"2026-11-20","startAt":"10:00"}'
```

## Ограничения и ошибки

- Название списка — до 60 символов; у ключа не больше 30 списков (`409`), переименовать в название другого своего списка нельзя (`409`).
- Название — до 200 символов, заметка — до 4000, отчёт — до 1000; у задачи хранятся 20 последних отчётов. Тело запроса — до 16 КБ. Неизвестные поля (`listId`, `done`, `helper` …) не принимаются — `400`.
- На ключ: 30 новых задач в час, 10 новых списков в час, 60 изменений в час, 120 чтений в минуту; сверх — `429` с `Retry-After`. Одновременно у ключа не больше 500 задач (`409`).
- Неверный или отозванный ключ — `401`; 10 неверных ключей с одного IP за 15 минут — этот IP получает `429` (другие адреса работают).
- Чужая, удалённая или несуществующая задача или список — `404` (ответ одинаковый, ничего не раскрывается). `DELETE` — всегда `405`, и для задач, и для списков.
- Изменения идут через то же хранилище, что и синхронизация устройств, и сливаются по полям: если вы в это время правите задачу на телефоне, обе правки разных полей сохранятся.
- В журнале сервера — `helper.create key=<id>` и т. п. (только номер ключа, не сам ключ), `helper.bad_key`, `helper.rate_limited`.
