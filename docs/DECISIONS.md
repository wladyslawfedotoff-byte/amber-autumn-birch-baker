# Ключевые решения

Решения восстановлены по истории git и описаниям PR. Дата — день, когда решение попало в `main` (по московскому времени). Если день по git не проверить, указана версия или пометка «правило проекта». Новые решения дописываются сверху в том же PR, где они реализованы.

| Дата / версия | Решение | Почему |
| --- | --- | --- |
| 2026-11-12, после 1.26.0 | **Проекты для ключей помощника отложены.** Ключ помощника работает только с задачами и списками. | Решение принято в обсуждении после 1.26.0; в коде и истории git его нет. Сначала нужен опыт со списками, а доступ бота к проектам потребовал бы отдельной модели прав на этапы и чужие карточки. |
| 2026-11-12 · 1.26.0 (PR #40) | **Списки для ключей помощника.** Ключ создаёт свои списки и переименовывает их. Создание идемпотентно по имени, действуют лимиты (60 символов, 30 списков, 10 действий в час). Чужие списки ключу не видны, задачу можно положить только в свой список. | Боту нужно раскладывать свои задачи, но доступ к личным спискам владельца давать нельзя. |
| 2026-11-12 · 1.25.0 (PR #39) | **Ключи помощника: только свои записи, без удаления.** Отдельный ключ на каждого бота, на сервере хранится только хэш. Ключ видит и правит только созданные им задачи, удалить ничего не может, все действия пишутся в журнал. Смена пароля и «Выйти на всех устройствах» отзывают ключи. | Бот с ключом может ошибиться или ключ может утечь. Ограниченные права, журнал и лимиты сужают ущерб, а удаление остаётся за человеком. |
| 2026-11-11 · 1.24.0 (PR #38) | **Проекты — горизонтальная доска, карточка = задача.** Принадлежность хранится в задаче (`projectId`, `stageId`, `projectOrder`). Последний этап означает «выполнено». Схема базы не меняется. | Одна сущность вместо копий, одна и та же карточка задачи везде. Правки с разных устройств сливаются по задачам, а не перезаписывают проект целиком. |
| 2026-10-31 · 1.23.0 (PR #37) | **«Вмещает дела».** Задача с началом и концом (например, смена) вмещает задачи, которые целиком лежат в её времени, и такие задачи не считаются накладкой. Задача, которая вылезает за край, или две пересекающиеся задачи внутри — по-прежнему накладка. | Рабочая смена не должна делать накладкой каждое дело внутри неё, но настоящие пересечения терять нельзя. Флаг хранится в задаче, миграция не нужна. |
| 2026-10-25 · 1.17.0–1.22.0 (PR #28–#35) | **Полировка вместо новых функций.** Шесть выпусков подряд с пометкой «Новых функций нет»: скорость, контраст, единый вид. | Приложение уже покрывало основные сценарии; важнее было сделать его быстрым, ровным и удобным на iPhone. |
| 2026-10-25 · 1.21.0 (PR #34) | **Высокий приоритет — красный.** Сегмент «Высокий» и метка строки задачи используют тон `danger`. | Высокий приоритет должен быть заметен сразу и не путаться с основным оранжевым акцентом. |
| 2026-10-25 · 1.20.0 (PR #33) | **Единый дизайн-код и оранжевый акцент.** Все цвета, отступы, радиусы и шрифты — токены в `src/tokens.css` и `src/lib/design/tokens.ts`. Оранжевый — основной цвет с контрастом не ниже 4,5:1. Произвольные цвета запрещает `scripts/check-raw-colors.mjs`, контраст проверяет `scripts/contrast.mjs` (оба в `npm run lint`). | Один источник правды для внешнего вида; проверки в CI не дают ему расползтись. |
| 2026-10-25 · 1.18.0 (PR #29) | **Дизайн в стиле iPhone.** Крупные заголовки, шторки снизу, системный шрифт, тонкие иконки. | Основное устройство — iPhone с ярлыком на главном экране. |
| 2026-10-22 · 1.13.2 (PR #23) | **Проверки в CI до сборки образа**: типы, тесты, линт и запрет названий других приложений (`scripts/brand-check.mjs`; сам скрипт есть с 2026-10-05, в CI — с 1.13.2). | Ошибки и лишние упоминания ловятся до публикации образа. |
| 2026-10-21 · 1.13.0 (PR #21) | **Быстрое добавление по ключу устройства.** Ключ умеет только добавлять во «Входящие», хранится хэш, есть лимиты. | Нужно отправлять задачи из меню «Поделиться» без входа в браузере и без выдачи полного доступа. |
| 2026-10-19 · 1.12.0 (PR #20) | **SQLite вместо JSON-файлов.** Документ синхронизации разложен по таблицам, отметки полей сохраняются как есть. Перенос однократный, со сверкой; скрипт отката на JSON (`scripts/db-downgrade-1.12.mjs`) добавлен в 1.13.0. | Транзакции и целостность при росте данных, при этом протокол синхронизации не меняется. |
| 2026-10-13 · 1.8.0 (PR #13) | **Работа без сети.** Локальная копия в IndexedDB, очередь отправки, service worker, слияние по полям. | Приложением пользуются с телефона, где связь бывает плохой. |
| 2026-10-11 · 1.6.0 (PR #9) | **Помощник с цепочкой моделей и подтверждением.** Сначала модель в домашней сети, затем бесплатные, платная последней. Изменения применяются только после «Применить». | Экономия денег и приватность; модель не меняет данные без согласия. |
| 2026-10-06 · 1.1.0 (PR #3) | **Профили на одном сервере.** Один набор сущностей с владельцем, совместные и назначенные задачи, сервер не доверяет клиенту. | Семья или команда на одном NAS без отдельных установок. |
| 2026-10-06 · 1.0.0 (PR #1) | **Самостоятельное размещение, секреты только в `.env` на NAS.** Публичный образ GHCR без секретов. Приложение слушает `127.0.0.1:8080` за обратным прокси NAS. Без пароля сервер закрыт. | Данные остаются дома. Публичный образ скачивается без токена. Секреты не попадают ни в git, ни в образ. (2026-10-05 образ сначала публиковался как приватный; с 1.0.0 документация описывает публичный образ.) |
| Правило проекта (дата по git не проверяется) | **Нет связи между GitHub и NAS и нет автообновления.** CI только публикует образ, а NAS обновляется вручную («Остановить» → «Собрать» в Container Manager) после копии данных. | NAS не хранит доступов к GitHub, и обновление происходит только тогда, когда владелец сам решил и сделал копию. Ручное обновление описано в [`SYNOLOGY.md`](SYNOLOGY.md) с 1.0.0. |
| Правило проекта | **Слияние в `main` — только с явного согласия владельца**, PR с нейтральными названиями, без личных имён, настоящих адресов и IP. | Репозиторий публичный, а каждое слияние сразу публикует новый образ. |
